# MyXTRV32 v0.4 三级流水线 —— 逐周期设计

> 前置结论：v0.3.1 已用 Icarus Verilog 14.0 跑通（`scripts/sim_iv.py`），
> 输出与 Vivado xsim 完全一致（23 字节、LED 3 次、235945 ns）。
> 仿真链路可用，可以开始改 RTL。

## 0. 流水线寄存器与接口约定

| 名称 | 内容 |
|---|---|
| `IF/ID` | `instr`, `pc`, `valid` |
| `ID/EX` | `a_fwd`, `b_fwd`（前递后）, `rd`, `ctrl`（alu_op/mem_read/mem_write/reg_write/branch…）, `pc`, `valid` |
| `EX/MEM` | `alu_r`, `rd`, `ctrl`, `valid` |
| `MEM/WB` | `wb_data`, `rd`, `reg_write`, `valid` |

存储端口（全部组合地址 + 同步输出）：

```verilog
// ROM
always @(posedge clk) rom_dout <= rom_mem[rom_addr];   // rom_addr = pc[15:2]

// RAM
always @(posedge clk) begin
    if (ram_we) ram_mem[ram_addr] <= ram_wdata;
    ram_rdata <= ram_mem[ram_addr];
end
```

- `rom_addr` 接 **pc**（IF 级）
- `ram_addr` / `ram_we` / `ram_wdata` 接 **ID/EX 级组合输出**
- 两个存储器在同一个时钟沿完成“采样地址”，输出在下一拍整拍有效

## 1. 连续 LOAD → ADD → STORE

```asm
I0: lw   x1, 0(x2)        # x2 = 0x10000
I1: add  x3, x1, x4
I2: sw   x3, 4(x5)
```

假设进入流水线时 `x2`、`x4`、`x5` 已在寄存器堆中（无依赖）。

| 周期 | pc | ROM dout | IF/ID | ID/EX | EX/MEM | MEM/WB | RAM 端口 | 时钟沿动作 |
|---|---|---|---|---|---|---|---|---|
| T0 | P0 | — | — | — | — | — | — | 沿：pc←P0 |
| T1 | P1 | `mem[P0]` | I0 | — | — | — | — | 沿：IF/ID←I0 |
| T2 | P2 | `mem[P1]` | I1 | I0: 算 A0=x2+0，发 RAM | — | — | `addr=A0, we=0` | **沿 T2：RAM 采样 A0** |
| T3 | P3 | `mem[P2]` | I2 | I1: `x1_fwd = ram_rdata`，ALU=x1+x4 | I0: `mem[A0]` | — | `addr=A1(垃圾)` | **T3 整拍 `ram_rdata = mem[A0]`**；沿 T3：I0 写回 x1 |
| T4 | P4 | `mem[P3]` | I3 | I2: `x3_fwd = EX/MEM.alu_r`，发 `A2=4(x5)` | I1: x3 | I0 已退休 | `addr=A2, we=1, wdata=x3_fwd` | **沿 T4：写 RAM[A2]**；沿 T4：I1 写回 x3 |
| T5 | P5 | `mem[P4]` | I4 | I3 | I2 | I1 退休 | `we=0` | — |

两条前递路径在这段代码里各用了一次：

| 依赖 | 前递源 | 生效周期 | 为什么不能靠寄存器堆 |
|---|---|---|---|
| I1 用 I0 的 `x1` | **`ram_rdata`（组合）** | T3 整拍 | `x1` 要到 T3 沿才写回，I1 在 T3 期间就要用 |
| I2 用 I1 的 `x3` | **`EX/MEM.alu_r`** | T4 整拍 | `x3` 要到 T4 沿才写回 |

**零停顿成立的条件**（用户指出的时序约束）：

```
T_BRAM(clk→Q) + T_forward_mux + T_ALU + T_setup + T_route  <  10 ns
```

即 T3 这条路径：`RAM 输出 → 前递 MUX → ALU → ID/EX 寄存器`。
如果综合后 WNS < 0，退化方案：检测到 load-use 时在 T2 末插入 1 拍停顿，
让 `ram_rdata` 先写回寄存器堆，T4 再从寄存器堆读。

> 补充：数据端口的读不只来自 RAM。ROM 的 `.rodata`、UART 状态、GPIO、MTIME、
> PERF 都走同一条 `dmem_rdata` 通路，前递必须对**整条 dmem_rdata** 成立，
> 不能只对 RAM 输出做前递。顶层现有的“所有读口对齐到第 2 拍有效”语义必须保留。

## 2. 分支 Taken（含 ROM 预取与 Valid 对齐）

```asm
I0: beq  x1, x2, T      # taken
I1: add  ...            # 错误路径
T:  lw   x9, 0(x10)
```

分支在 **ID/EX 级**由 ALU 比较器判定，`pc_target` 同拍组合产生。

| 周期 | pc | ROM `addr` | ROM `dout` | IF/ID | ID/EX | 动作 |
|---|---|---|---|---|---|---|
| T0 | P1 | P1 | `mem[P0]` | I1 (valid=1) | I0: 比较 → **taken** | — |
| T0沿 | **T** | T | — | **valid=0**（冲刷 I1） | bubble | pc←T；flush IF/ID |
| T1 | T | T | `mem[P1]`（旧） | invalid | bubble | 沿 T1 前 ROM 采样 T |
| T1沿 | T | T | **`mem[T]`** | — | — | ROM 输出更新 |
| T2 | T+4 | T+4 | `mem[T]` | I_target (valid=1) | bubble | 沿 T2：IF/ID←`mem[T]` |
| T3 | T+8 | T+8 | `mem[T+4]` | I_t+1 | **I_target** | 恢复流动 |

**关键修正：惩罚是 2 拍，不是 1 拍。**

原因：分支在 T0 判定、T0 沿更新 pc，但 ROM 的 `dout` 要到 **T1 沿**才变成
`mem[T]`，而 IF/ID 在 T1 沿锁存的是沿前的旧值。真正拿到 target 指令是 T2 沿，
指令进入 ID/EX 是 T3。所以 T1、T2 两拍 ID/EX 是气泡。

按 CoreMark 实测分支占比 20% 估算：`+0.4 CPI`（此前按 1 拍估的 0.2 偏乐观）。

**Valid 规则**（三条，缺一不可）：

1. `IF/ID.valid` 在冲刷时清零，且只在“取到的确实是当前 pc 流的指令”时置 1
2. `ID/EX.valid = IF/ID.valid && !stall`（气泡不参与写回/访存）
3. 退休脉冲只由 `MEM/WB.valid` 产生 → 被冲刷的指令永不计数

**stall 期间 ROM 会继续输出**：BRAM 的读是“地址采样后固定输出”，
即使冻结 pc，T1 沿采样到的仍是 T 的数据。所以 stall 时必须同时冻结
`IF/ID` 的更新（不锁存新数据），而不是指望 ROM 不输出。冲刷后 IF/ID 的
`valid=0` 正好屏蔽掉这些“多取到的”指令。

## 3. MUL / DIV 阻塞

```asm
I0: add  x5, x6, x7
I1: div  x1, x2, x3      # 33 拍
I2: add  x8, x1, x9      # 依赖 x1
```

| 周期 | IF/ID | ID/EX | EX/MEM | MEM/WB | 说明 |
|---|---|---|---|---|---|
| T1 | I1 | **I0** | — | — | 正常流动 |
| T2沿 | I1(冻结) | **I1: 进入 DIV** | I0 | — | 沿 T2：I0 → MEM/WB |
| T2..T34 | I1(冻结) | I1: div_cnt 32→0 | — | **bubble (valid=0)** | 沿 T3 起 MEM/WB 每拍插气泡 |
| T34沿 | I1(冻结) | I1: 完成，`alu_r=结果` | — | bubble | — |
| T35沿 | I2 | **I1 → MEM/WB** | — | I1 (valid=1) | 沿 T35：I1 写回 x1，**仅此一次** |
| T36 | I3 | I2: 前递 `x1`（来自 MEM/WB） | I1 | I2 | 恢复 |

三条硬性规则：

1. **更老的指令正常退休**：I0 在 DIV 开始的下一拍就写回，不受阻塞影响。
2. **MEM/WB 必须插 Bubble**：DIV 期间 `MEM/WB.valid = 0`，否则会在 33 拍里
   反复退休同一条指令（这是最容易写错的地方）。
3. **DIV 只提交一次**：结果在结束时锁存进 `ID/EX.alu_r`，下一拍随正常路径进
   `MEM/WB`，`valid` 只拉高一次。

**不会重复触发的副作用**：`store`、UART/GPIO 写都发生在 ID/EX 级。
DIV/MUL 阻塞时占用 ID/EX 的是乘除法指令本身，`store` 被挡在 `IF/ID`，
因此在阻塞期间不会重复写 RAM 或 MMIO。

**MUL**：沿用 v0.3 的两拍结构（DSP 输出锁存 → 有符号高位修正），
只在 ID/EX 多停 1 拍（`stall_mul`），同样冻结 IF/ID、MEM/WB 插气泡。
不要把 DSP 与 64 位修正合并回一拍——v0.3 实测该路径 WNS −3.612 ns。

## 4. 计数器地址修正

现有 `myxtrv32_top.v` 用 `case (A[4:2])` 译码 8 个寄存器，而新方案用到
`0x0002_0330`，`A[4:2]` 会回绕（`0x320` 与 `0x300` 别名）。

修正：索引扩展到 **`A[5:2]`**（16 个槽位），`sel_perf` 仍为 `A[31:8]==0x0002_03`。

| 偏移 | 计数 |
|---|---|
| 0x00 | instret |
| 0x04 | alu |
| 0x08 | load |
| 0x0C | store |
| 0x10 | 分支/跳转（总计） |
| 0x14 | mul |
| 0x18 | div |
| 0x1C | branch_taken（条件分支，不含 JAL/JALR） |
| 0x20 | branch_not_taken（条件分支） |
| 0x24 | jal_jalr |
| 0x28 | stall_load_use |
| 0x2C | stall_mul |
| 0x30 | stall_div（拍数） |
| 0x34 | flush（冲刷次数） |

CPI 定义修正：

```
CPI = cycles / instret
```

（原文写成 `instret / cycles`，是笔误。）

| 测试 | 覆盖 |
|---|---|
| `tb_smoke` | 现有 sim_test，23 字节、LED 3 次 |
| `tb_load_use` | `lw→add`、`lw→sw`、`lw→lw` 同址，验证 T3 前递 |
| `tb_fwd` | 连续 `addi/add/sub` 相邻依赖，验证 EX/MEM 前递 |

每个 tb 都统计 `instret`，与程序里手工数的指令条数比对——这是“每条指令
只退休一次”的硬性检查。
