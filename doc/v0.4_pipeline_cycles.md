# MyXTRV32 v0.4 三级流水线 —— 逐周期设计

> 前置结论：v0.3.1 已用 Icarus Verilog 14.0 跑通（`scripts/sim_iv.py`），
> 输出与 Vivado xsim 完全一致（23 字节、LED 3 次、235945 ns）。
> 仿真链路可用，可以开始改 RTL。

## 0. 流水线寄存器与接口约定

| 名称 | 内容 |
|---|---|
| `IF/ID` | **数据寄存器就是 ROM 内部的 `dout`**，不额外加 `if_id_instr`；只附加两个轻量标签 `if_id_pc`、`if_id_valid`，与 `dout` 在同一沿更新 |
| `ID/EX` | 纯组合级：译码、读寄存器堆、前递 MUX、ALU、地址生成 |
| `EX/MEM` | `alu_r`, `rd`, `ctrl`, `valid` |
| `MEM/WB` | v0.4 骨架阶段只有写回（无独立寄存器）；接入 LOAD 后由 RAM 同步输出承担数据寄存器 |

**关键：不设额外的取指寄存器。** ROM 的 `always @(posedge clk) dout <= mem[addr]`
本身就充当了 IF/ID 的数据寄存器，ID/EX 的组合逻辑直接以 `dout` 为输入。
如果再加一级 `if_id_instr <= rom_dout`，取指会多一拍、分支罚时也会从 1 拍变成 2 拍。

存储端口（全部组合地址 + 同步输出）：

```verilog
// ROM
always @(posedge clk) rom_dout <= rom_mem[rom_addr];   // rom_addr = pc[15:2]

// RAM
always @(posedge clk) begin
    if (ram_we) ram_mem[ram_addr] <= ram_wdata;
    ram_rdata <= ram_mem[ram_addr];
end
```

- `rom_addr` 接 **pc**（IF 级）
- `ram_addr` / `ram_we` / `ram_wdata` 接 **ID/EX 级组合输出**
- 两个存储器在同一个时钟沿完成“采样地址”，输出在下一拍整拍有效

## 1. 连续 LOAD → ADD → STORE

```asm
I0: lw   x1, 0(x2)        # x2 = 0x10000
I1: add  x3, x1, x4
I2: sw   x3, 4(x5)
```

假设进入流水线时 `x2`、`x4`、`x5` 已在寄存器堆中（无依赖）。

| 周期 | pc | ROM dout | IF/ID | ID/EX | EX/MEM | MEM/WB | RAM 端口 | 时钟沿动作 |
|---|---|---|---|---|---|---|---|---|
| T0 | P0 | — | — | — | — | — | — | 沿：pc←P0 |
| T1 | P1 | `mem[P0]` | I0 | — | — | — | — | 沿：IF/ID←I0 |
| T2 | P2 | `mem[P1]` | I1 | I0: 算 A0=x2+0，发 RAM | — | — | `addr=A0, we=0` | **沿 T2：RAM 采样 A0** |
| T3 | P3 | `mem[P2]` | I2 | I1: `x1_fwd = ram_rdata`，ALU=x1+x4 | I0: `mem[A0]` | — | `addr=A1(垃圾)` | **T3 整拍 `ram_rdata = mem[A0]`**；沿 T3：I0 写回 x1 |
| T4 | P4 | `mem[P3]` | I3 | I2: `x3_fwd = EX/MEM.alu_r`，发 `A2=4(x5)` | I1: x3 | I0 已退休 | `addr=A2, we=1, wdata=x3_fwd` | **沿 T4：写 RAM[A2]**；沿 T4：I1 写回 x3 |
| T5 | P5 | `mem[P4]` | I4 | I3 | I2 | I1 退休 | `we=0` | — |

两条前递路径在这段代码里各用了一次：

| 依赖 | 前递源 | 生效周期 | 为什么不能靠寄存器堆 |
|---|---|---|---|
| I1 用 I0 的 `x1` | **`wb_data`（`ram_rdata` 经 LB/LH 提取与符号扩展后）** | T3 整拍 | `x1` 要到 T3 沿才写回，I1 在 T3 期间就要用 |
| I2 用 I1 的 `x3` | **`EX/MEM.alu_r`** | T4 整拍 | `x3` 要到 T4 沿才写回 |

**前递的必须是最终写回值 `wb_data`，不是原始 `ram_rdata`。**
`LB/LBU/LH/LHU` 需要字节/半字提取和符号（或零）扩展，如果只旁路 32 位原始输出，
这些指令的前递结果就是错的。

因此 load-use 的真实关键路径比之前的估计更长：

```
BRAM(clk→Q) → 读数据选择(ROM/RAM/MMIO) → 字节/半字提取 → 符号扩展 → 前递 MUX → ALU → Setup
```

这条路径必须用 Vivado 实测，不能只按 `BRAM + MUX + ALU` 估算。
v0.4 的 `wb_data` 生成逻辑沿用 v0.3.1 的 `ld_shift` + `ld_ext` 结构，前递点放在 `ld_ext` 之后。

另外，数据端口的读不只来自 RAM。ROM 的 `.rodata`、UART 状态、GPIO、MTIME、
PERF 都走同一条 `dmem_rdata` 通路，前递必须对**整条 `wb_data`** 成立，
不能只对 RAM 输出做前递。顶层现有的“所有读口对齐到第 2 拍有效”语义必须保留。

## 2. 分支 Taken（含 ROM 预取与 Valid 对齐）

```asm
I0: beq  x1, x2, T      # taken
I1: add  ...            # 错误路径
T:  lw   x9, 0(x10)
```

分支在 **ID/EX 级**由 ALU 比较器判定，`pc_target` 同拍组合产生。

因为 **ROM 的 `dout` 寄存器直接充当 IF/ID**，分支惩罚是 **1 拍**（不是 2 拍）：

| 周期 | pc | ROM `dout` | ID/EX 正在执行的指令 | EX/MEM（沿） |
|---|---|---|---|---|
| T0 | P0 | `mem[P-1]` | — | — |
| T1 | P1 | `mem[P0]` | **I0（分支）** | — |
| T2 | **T** | `mem[P1]` | I1（错误路径） | 沿 T2：I0，`pc←T` |
| T3 | T+4 | **`mem[T]`** | I_target | 沿 T3：**I1 被冲刷（valid=0）** |
| T4 | T+8 | `mem[T+4]` | I_t+1 | 沿 T4：I_target |

- 分支在 I0 的 ID/EX（T1–T2）判定，T2 沿改 `pc`
- I1 在 T2–T3 已是 ID/EX 组合级，无法撤回，只能在 **T3 沿把它的 `valid` 清零**
- target 的指令在 T3 沿随 `dout` 更新而出现，T4 沿进 EX/MEM
- **净损失：1 个 EX/MEM 槽位（T3 沿的气泡）**

如果多一级 `if_id_instr` 寄存器，target 要 T4 才进 ID/EX、T5 才进 EX/MEM，就变成 2 拍。

**Valid 规则**（三条，缺一不可）：

1. `if_id_valid` 与 `dout` 同沿更新；冲刷时在**同一沿**清零，屏蔽掉错误路径指令
2. `ex_mem_valid = if_id_valid && !stall`（气泡不写回、不访存）
3. 退休脉冲只由 `ex_mem_valid`（接入 MEM/WB 后是 `mem_wb_valid`）产生 → 被冲刷的指令永不计数

**stall 期间 ROM 会继续输出**：BRAM 是"采样地址后固定输出"，冻结 `pc` 后它每拍
重复输出同一字。因此 stall 时必须冻结 `if_id_valid`/`ex_mem_valid` 的更新，
而不是指望 ROM 停下来。冲刷后 `valid=0` 正好屏蔽这些多取到的指令。

## 3. MUL / DIV 阻塞

```asm
I0: add  x5, x6, x7
I1: div  x1, x2, x3      # 33 拍
I2: add  x8, x1, x9      # 依赖 x1
```

| 周期 | IF/ID 标签 | ID/EX | EX/MEM | 写回 | 说明 |
|---|---|---|---|---|---|
| T1 | I1 | I0 | — | — | 正常流动 |
| T2 沿 | I1（冻结） | **I1 进入 DIV** | I0 | — | I1 移入执行级，IF/ID 保持 I2 的取指位置 |
| T2–T3 | I1 | I1 迭代 | I0 | **沿 T3：I0 写回** | 老指令正常退休 |
| T3 沿 | I1 | I1 迭代 | **bubble（valid=0）** | — | 从这一沿起 EX/MEM 每拍插气泡 |
| T4–T34 | I1 | I1 迭代 | bubble | — | —— |
| T34 沿 | I1 | I1 完成，结果锁存 | bubble | — | — |
| T35 沿 | **I1 清除** | 空闲 | **I1（valid=1）** | — | 结果进入 EX/MEM |
| T36 沿 | I2 | I2 | I1 | **沿 T36：I1 写回 x1，仅一次** | 恢复 |

三条硬性规则：

1. **指令位置唯一**：I1 进入 DIV 时占据的是**执行级（ID/EX）**；
   `IF/ID` 里的标签只用于记住“下一条该取哪”（I2 还没取到，`pc` 已指向 I2）。
   同一条指令不会同时出现在两个流水级——ID/EX 是组合级，I1 停在那里，
   IF/ID 的标签保持不变。
2. **MEM/WB 必须插 Bubble**：DIV 期间 `EX/MEM.valid = 0`，否则会在 33 拍里
   反复让同一条指令进入写回。
3. **按非阻塞赋值语义描述**：EX/MEM 在 T35 沿锁存 I1 的结果，寄存器堆的写入
   发生在**下一个沿（T36）**。文档前一版写“T35 沿进入 MEM/WB 同时写回”是不准确的。

**不会重复触发的副作用**：`store`、UART/GPIO 写都发生在 ID/EX 级。
DIV/MUL 阻塞时占用 ID/EX 的是乘除法指令本身，`store` 被挡在 `IF/ID`，
因此在阻塞期间不会重复写 RAM 或 MMIO。

**MUL**：沿用 v0.3 的两拍结构（DSP 输出锁存 → 有符号高位修正），
只在 ID/EX 多停 1 拍（`stall_mul`），同样冻结 IF/ID、MEM/WB 插气泡。
不要把 DSP 与 64 位修正合并回一拍——v0.3 实测该路径 WNS −3.612 ns。

## 4. 计数器地址修正

现有 `myxtrv32_top.v` 用 `case (A[4:2])` 译码 8 个寄存器，而新方案用到
`0x0002_0330`，`A[4:2]` 会回绕（`0x320` 与 `0x300` 别名）。

修正：索引扩展到 **`A[5:2]`**（16 个槽位），`sel_perf` 仍为 `A[31:8]==0x0002_03`。

| 偏移 | 计数 |
|---|---|
| 0x00 | instret |
| 0x04 | alu |
| 0x08 | load |
| 0x0C | store |
| 0x10 | 分支/跳转（总计） |
| 0x14 | mul |
| 0x18 | div |
| 0x1C | branch_taken（条件分支，不含 JAL/JALR） |
| 0x20 | branch_not_taken（条件分支） |
| 0x24 | jal_jalr |
| 0x28 | stall_load_use |
| 0x2C | stall_mul |
| 0x30 | stall_div（拍数） |
| 0x34 | flush（冲刷次数） |

CPI 定义修正：

```
CPI = cycles / instret
```

（原文写成 `instret / cycles`，是笔误。）

每个 tb 都统计 `instret`，与程序里手工数的指令条数比对——这是“每条指令
只退休一次”的硬性检查。
